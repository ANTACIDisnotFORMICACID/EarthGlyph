# DECISIONS — 重要设计决策及依据

记录格式：**D# 决策** — 状态（已定 / 假设-待验证）— 依据 — 影响。
新决策追加，不删除历史；状态变化时更新并注记日期。

## 架构

**D1 静态优先，无运行时后端** — 已定
依据：降低 Qoder Sites 额度与复杂度依赖；V1 候选规模（1–5 万）可在浏览器 Worker 内检索。
影响：索引产物为静态文件；前后端共用特征 / 精排约定。规模超预算时再升级 FastAPI+FAISS（见 ARCHITECTURE §2）。

**D2 两级检索（粗筛 + 精排）** — 已定
依据：粗筛保速度，精排保效果；避免全量精排的 O(N) 高成本。
影响：需维护低维粗筛特征 + 128 点精排轮廓两套产物。

**D5 Baseline 先行，不急于深度学习** — 已定
依据：缺乏可解释基线时引入模型无法判断收益，且违背"真实可行 > 扩展"原则。
影响：P0 必须先建 Hu/Fourier/Chamfer 基线并有实验对照。

## 数据与几何

**D3 局部投影，不把经纬度当欧氏 x/y** — 已定
依据：东西方向尺度随纬度变化，直接当平面坐标会 distort 形状与距离。
影响：每个候选用局部等距投影转米制；极区 / 跨 180° 经线单独处理。

**D4 MultiPolygon 拆为独立候选并记录 parent_id** — 已定
依据：离散水面合成单一轮廓会产生怪异形状，污染检索。
影响：去重阶段需按 parent_id 折叠同源重复部分。

**D6 数据首选 Overture Base/Water，subtype 限 lake/pond/reservoir** — 已定
依据：Schema 明确、许可清晰（ODbL）、字段含来源 ID 可回查。
影响：过滤规则与许可署名见 DATA_PIPELINE.md。

**D7 弧长均匀采样 128 点** — 已定（2026-11-05 由 P0-3 实测确认，结论见 D29）
依据：兼顾表达力与计算量；64/256 的影响待实验。
影响：P0 需做采样点数消融；若 128 不足则调整。
注记（2026-11-05，P0-2 实测）：839 个候选的弧长步长偏差中位数约 0.5%，但枝状水库
（如 `4b2c4aea-…-part1`，2,269.8 ha、全边界约 213 km）最坏偏差约 104% —— 128 点无法
表达极端枝状岸线。该证据支持 P0-3 的采样点数消融（含按复杂度自适应 N 的选项）。
注记（2026-11-05，P0-3 复核）：该 "104%" 是弦长离散度 `chord_dispersion`，不是重建误差，
P0-3 实测 N=128 下该候选的真实归一化 Hausdorff 为 0.1483、region IoU 为 0.8104（见 D29/D30）。

## 算法

**D8 精排旋转对齐用复数相关求 θ，不暴力遍历 360°** — 已定
依据：闭式解更快更稳。
影响：实现须处理循环移位 s 与 θ 的联合最优。

**D9 镜像必须显式反射（复共轭），由用户开关控制** — 已定
依据：逆序采样只改走向，不等于镜像；混淆会导致错误匹配解释。
影响：精排与前端开关须一致。

**D10 Fourier 幅值仅用于粗筛** — 已定
依据：幅值降低平移 / 缩放 / 起点 / 旋转影响，但丢结构、不区分镜像。
影响：镜像区分与结构匹配留给精排。

## 产品

**D11 score 为内部排序代价，非展示用"相似度百分比"** — 已定
依据：避免人为制造相似度数字误导用户。
影响：前端不显示"98% 相似"类文案。

**D12 representative point 须在多边形内部** — 已定
依据：质心可能落在水体之外（凹形 / 环状）。
影响：metadata 的地图点用 shapely representative_point，非 centroid。

## 数据获取（P0-1 实测后新增）

**D13 数据获取默认走 STAC 索引 + DuckDB httpfs range 读取，官方 CLI 作为可选路径** — 已定（2026-11-04）
依据：本机 pyarrow 的 S3 SDK 直连 Overture 数据桶出现响应截断（GetObject 长度与 content-length
不符，只落盘 5KB 残片），urllib 偶发 `WinError 10048`；而 DuckDB httpfs 对同一批公共 HTTPS 对象
做 parquet row-group range 读取稳定，且只传输与 bbox 相交的数据（~5.5MB vs 源文件 1.2GB×32）。
文件地址取自官方 STAC 索引 `stac.overturemaps.org/<release>/collections.parquet`，
bbox 过滤语义与官方 CLI 完全一致（feature bbox struct 与查询框相交）。
影响：`scripts/download_data.py --fetch-method {duckdb,cli}`，sidecar 记录 `fetch_method` 与
`cli_equivalent`；输出需手写 GeoParquet 1.0 `geo` 元数据（WKB + EPSG:4326）保持格式合法。
换环境或网络恢复时可用 `--fetch-method cli` 复现同一结果，两条路径都保留。

**D14 Schema 以实际下载数据为准：subtype/class 为字符串，并新增可用字段** — 已定（2026-11-04）
依据：release 2026-10-21.0 实测 15 列，`subtype`/`class` 是字符串而非设计文档假设的列表；
数据含 `is_intermittent` / `is_salt` / `level` / `source_tags` / `wikidata`。
影响：`_category_key` 同时兼容标量与列表（防未来 Schema 回退）；P0-2 过滤可用
`is_intermittent`（间歇水体形状易退化）与 `is_salt`；设计文档 §2.1 的字段清单按 DATA_PIPELINE §8.2 修正。

**D15 排除 feature bbox 触及下载框边缘的记录** — 已修订（2026-11-05；原 2026-11-04 规则作废）
原依据：威斯康星样本中面积最大（98 km²）的"水体"是被查询框切断的密歇根湖 / 格林湾边缘，
属于切片伪轮廓而非真实闭合形状。
修订依据（P0-2 几何证据，task #14）：对 release 2026-10-21.0 该 bbox 的 1,984 个可用
多边形逐一检查，**0 个**的外环顶点或边落在下载框边界上；17 个 feature 的 bbox 超出下载框，
但逐一核对均为**完整几何**（其中最大者是密西西比河河道水池，而非被切断的密歇根湖边缘）。
即 Overture 的 bbox 相交查询返回完整 feature，"bbox 触及框边 = 被裁剪"不成立。
修订后规则：P0-2 管道**不**按框边接触过滤；改为记录信息性标志
`extends_beyond_frame`（839 个候选中 8 个为 true），供后续扩大 bbox 时复核。
影响：`prepare.py` 不再丢弃框边地物；`preview_data.py` 的 `_touching_frame` 仅保留为
P0-1 预览选样的保守手段（实测不会剔除任何真实地物），不作为索引构建规则。

**D16 米制量算统一用局部方位等距投影 aeqd（以样本中心为原点）** — 已定（2026-11-04）
依据：落实 D3。实测 `+proj=eqa` 不是合法 PROJ 投影名；`aeqd` 必须显式给 `+ellps=WGS84`，
否则 pyproj 报 "Must specify ellipsoid or sphere"。geopandas 在地理 CRS 下直接取 `.area`
得到的是平方度且会告警，故面积 / 分层抽样一律先投影。
影响：`inspect.py` / `preview_data.py` 使用
`+proj=aeqd +lat_0=<中心纬> +lon_0=<中心经> +ellps=WGS84 +units=m +no_defs`；
P0-2 特征提取沿用同一约定并写入 manifest（跨纬度、极区、180° 经线仍需专门处理）。

**D17 复现性以"内容摘要"为准，文件 sha256 仅作辅助** — 已定（2026-11-04）
依据：同一不可变 release 两次下载得到逻辑内容完全相同（15 列逐列相等、行序一致）但物理字节
不同的文件 —— 差异来自取数代码的 chunk 策略（`fetch_arrow_table()` 零拷贝多 chunk →
`to_arrow_table()` 单 chunk）改变 parquet 页 / 字典布局，而非数据变化。若只以文件 sha256
判定复现，会在依赖升级后误判为"数据变了"。
影响：`data_manifest.json`（P0-2）同时记录文件 sha256 与内容摘要（排序后的 id→WKB 摘要）；
审计时优先比对内容摘要 + 行数 + release；已用当前代码重下并覆盖入库文件，使"入库文件"与
"入库代码"字节一致，旧副本保留待清理。

## 几何清洗与标准化轮廓（P0-2，2026-11-05 新增）

**D18 过滤采用 feature 级 / part 级两级记账，并留存被过滤样本** — 已定
依据：单一计数无法区分"整条记录不可用"与"拆分后某个 part 不可用"，也无法回答
"过滤是否过度"；任务要求输出每项过滤条件影响的候选数量并保存部分被过滤形状。
影响：manifest 记录 `rejected_features_by_reason` 与 `rejected_parts_by_reason`，
恒等式 `raw_rows = rejected_features + features_reaching_part_stage`、
`parts_extracted = candidates + rejected_parts` 由单测强制；
`rejected_samples.parquet` 按原因各存至多 200 条真实形状供目视检查。

**D19 允许表之外的多边形不删除，落入 pending_analysis.parquet** — 已定
依据：river/canal/human_made/未标注 water 等 1,034 个多边形只是"当前不检索"，
并非错误数据；删除会丢失后续分析机会，违背"可保留为待分析数据"的要求。
影响：`pending_analysis.parquet` 保存其米制面积、part 数与 WKB；候选库只含
lake/pond/reservoir（`--subtypes all` 可关闭允许表）。

**D20 最小面积阈值是实验参数，默认 0.1 ha，不是硬规则** — 已定
依据：任务明确"最小面积暂以 0.1 ha 为实验参数，不得硬编码为不可更改的规则"；
且面积下限的合理值依赖检索目标（小池塘 vs 大湖）。
影响：`scripts/prepare_polygons.py --min-area-ha`；manifest 记录实际取值；
被该规则拒绝的 121 个真实形状已留存，图 C 的面积直方图用于判断是否过度过滤。

**D21 标准化轮廓只存外环；孔洞与部件信息入 metadata；candidate_id 可回查** — 已定
依据：孔洞（岛屿）对"手绘外轮廓"检索是噪声，但孔洞数量是有用的元数据；
MultiPolygon 必须拆 part（D4）且保留父级链接。
影响：`contour` 为外环 128 点；`n_holes`、`part_index`、`n_parts`、`source_id`、
代表点经纬度入库；`candidate_id = source_id`（单 part）或 `source_id-partK`（多 part），
单测验证代表点落在源 part 内、面积与轮廓可由原始几何复算。

**D22 高重叠去重：IoU > 0.95 视为重复，保留面积最大者** — 已定
依据：Overture 同源水面存在几乎完全重叠的重复要素；保留较大者避免同一水面占两个候选。
影响：`resolve_duplicates` 用 STRtree + 并查集聚类；本 release 真实数据中 2 对高 IoU
（0.9982 / 0.9822）均为**跨 subtype**（pond/water、human_made/water），允许表内 0 触发，
故 839 候选无去重损失；合成单测覆盖同表内去重路径。

**D23 预处理输出对旋转协变而非不变；旋转/循环对齐与镜像开关留在检索阶段** — 已定
依据：D8/D9 的对齐属于匹配代价的一部分；若在预处理"归一化掉"旋转或起点，
会破坏镜像区分并提前丢失判别信息。
影响：`normalize_contour` 只做平移 + RMS 缩放 + CCW 走向统一（走向≠镜像）；
单测断言旋转后轮廓随之旋转、镜像轮廓不与原轮廓重合、循环起点不被对齐。

## 特征与索引（P0-3，2026-11-05 新增）

**D24 粗筛特征 = 低谐波 Fourier 幅值描述子（DC 丢弃、逐样本除以 N、按谐波序号排列）** — 已定
依据：z=x+iy 的 DFT 中 `Z_0` 是质心（携带位置而非形状），必须丢弃；不除以 N 时幅值随采样点数
线性增长，64/128/256 的描述子不可比 —— Task C 的采样消融正依赖这一点。
影响：`earthglyph/features/fourier.py` 提供 `per_sample=True`（默认）；查询端必须用同一定义；
描述子按谐波索引 k 定址排列，**不按数值排序**（排序会破坏 k 的语义）。

**D25 谐波数取 16（在 12 / 16 / 24 三者中）** — 已定
依据（`experiments/p0_feature_probe/features_summary.json`，839 个真实候选）：
非 DC 谱能量捕获中位数 h12=0.9007 / h16=0.9008 / h24=0.9010（p10 均为 ~0.702）；
两两成对距离相关 pearson ≥ 0.99997、Top-10 近邻重合 mean 0.98（h12 vs h16）/ 0.9875（h24 vs h16）；
h16 相比 h12 仅把最近邻中位距离从 0.02146 抬到 0.02180，即分离度增益 < 2%。
影响：默认 `DEFAULT_N_HARMONICS = 16`，索引 feature_dim = 16 + 4 = 20；
**该结论只是几何与特征空间层面的取舍，不构成检索精度提升的证据**（尚无真值对与手绘查询）。

**D26 折叠模式选 `positive`（只用 k≥1），不选 `symmetric`** — 已修订（2026-11-05 P0-4；原"保留镜像判别信息"的理由作废）
依据（更正）：在**未固定走向的原始点列**上，走向反转使 `Z_k → Z_-k`、显式镜像使 `Z_k → conj(Z_-k)`，
两者都表现为 k↔−k 幅值互换（实测 arrow 轮廓：两个操作造成的差异逐谐波相同，gap 均为 0.679）。
但预处理已把走向固定为 CCW（D23）——规范化之后 `ensure_ccw` 把反转还原为同一条走向，
而规范镜像 `b^m_k = conj(b_{-k})` 满足 `Z^m_k = conj(Z_k)`，**幅值精确不变**。
实测（`tests/test_alignment.py::test_four_pipeline_variants_show_amplitudes_are_mirror_blind`；
稠密环 → CCW → 弧长重采样 → Fourier）：反转 gap = 0.0、旋转 gap = 2.1e-15、镜像 gap = 4.1e-8；
同一镜像对在几何精排下 D = 0.0595 / 0.0749。粗环（8 顶点多边形再采样）残留 4.7e-3
是弧长网格相位滑动，反转与旋转给出同量级偏差 → 属采样伪影，不是镜像信息。
影响：`positive` 仍为默认，但理由是"未规范化输入上更严格"，**不是**"能判别镜像"；
`symmetric` 折叠对已规范化轮廓冗余，仅作可选实现保留。
Fourier 幅值**镜像盲**，镜像开关一律由几何精排控制（D9/D33），不得依赖幅值的偶然数值差异；
该结论写进 `feature_definition` 的 `denied_capabilities` 并由 `tests/test_fourier.py` 断言。

**D27 辅助几何特征只保留 4 个无量纲统计量，且与 Fourier 组只做拼接不做加权融合** — 已定
依据：任务要求"各特征组保持独立以便消融"，且未验证的融合权重会掩盖哪一组在起作用。
影响：`compactness=4πA/P²`、`solidity=A/A_hull`、`aspect_ratio`=最小外接矩形长短边比、
`diameter_fill=4A/(πD²)`，全部在**标准化采样轮廓**（外环、闭合到自身）上计算，
定义写入 manifest 的 `features.geometry.formulas`；查询端必须同基准计算才可比。

**D28 最小外接矩形（长宽比）自实现凸包 + 旋转卡尺，不用 GEOS `minimum_rotated_rectangle`** — 已定
依据（实测）：GEOS 在本 release 的一个 40 顶点有效凸包上把矩形退化为面积 6.279e-18 的细条，
导致 aspect_ratio 出现非物理值；shapely 2.2.0 / GEOS 3.14.1。
影响：`earthglyph/features/geometry_stats.py` 自带 Andrew monotone-chain 凸包与
旋转卡尺最小面积矩形；零面积 / 零周长 / 零凸包 / 零矩形宽度一律抛 `FeatureError`
并**计数**，不得静默丢弃候选。

**D29 采样点数默认仍为 N=128；不引入自适应 N** — 已定（解决 D7）
依据（`experiments/p0_feature_probe/sampling_summary.json`，839 个候选全部从**原始外环**
重新弧长采样，未使用"128 点插值到 256"的捷径）：
- 归一化 Hausdorff p50/p90/max = 0.0313/0.0708/0.2568（N=64）、0.0157/0.0344/0.1483（N=128）、
  0.0078/0.0178/0.0789（N=256）；region IoU 均值 0.9863/0.9949/0.9982，最小值 0.6772/0.8104/0.8959。
- 特征稳定性：与 N=128 参考相比，12 谐波幅值相对 L2 偏差 p50 为 4.85e-4（N=64）/ 1.18e-4（N=256），
  但 `compactness` 的 p99 相对偏差达 24.7%（N=64）与 16.2%（N=256）——
  **查询与候选必须用同一 N 标准化**，这比 N 取多大更关键。
- 成本：轮廓字节数随 N 线性翻倍（5 万候选：N=128 约 48.8 MiB，N=256 约 97.7 MiB），
  而粗筛扫描耗时几乎不变（839 候选全量 L2 扫描 1.7e-5 s）。
- 128→256 只把"达标候选数"从 152 抬到 31（在 iou≥0.95 且 hausdorff_norm≤0.05 目标下），
  另有 8 个候选在**任何**测试 N 下都不达标（其中 7 个为 reservoir）。
影响：V1 保持 `n_points=128`；自适应 N 未采纳（会破坏固定宽度批量读取与跨 N 可比性），
若 P0-4 精排证明极端枝状岸线是主要失败源，再作为独立特性引入。

**D30 曲线偏差用加密点云近似，误差上界 = 一个云步长且偏保守；已对精确参考做全校验** — 已定
依据：GEOS `hausdorff_distance` 是**顶点离散**距离（连续距离的下界），且对 8,085 顶点的
水库外环直接算连续距离不可控；本实现把两条曲线各按 `step/8` 加密后 kNN 求对称距离，
残差 ≤ 一个云步长且偏**高**（粗参考点云的最近点可能落在弦上而非垂足）。
实测校验（`--validate-exact`，2,517 对）：中位偏差 vs GEOS = 0.0122/0.0068/0.0038 m
（N=64/128/256），最大绝对偏差 6.21/2.97/0.73 m，
最大偏差 / 一个云步长 ≤ 0.12/0.46/0.43，**超出步长上界的对数 = 0**；
与 8× 更细点云比较同样 0 违例。
影响：报告中的 Hausdorff 是保守上界而非乐观估计；P0-2 流传的"最坏 104% 弧长步长偏差"
已重新归类为 `chord_dispersion`（弦长对均值的最大偏离比，N=128 实测 1.0448），
**不是**重建误差；另有一条硬约束：参与比较的点列必须先闭合，
否则真实候选的 Hausdorff 会从 520 m 变成 610 m（闭弦 1,258 m）。

**D31 索引产物 = 3 个文件 + manifest，float32 小端 C-order，行序契约由 metadata 自证** — 已定
依据：浏览器端需要能零拷贝解码的定长块，且"features[i] ↔ shapes[i] ↔ metadata 第 i 行"
必须由数据自身可验证，而不是靠约定信任构建脚本。
影响：`data/index/{features.npy (M×20 f4), shapes.npy (M×128×2 f4), metadata.parquet}`；
metadata 含 `feature_row` / `candidate_id` / `source_id` / `part_index` / `subtype` /
`lon` / `lat`（representative point，D12）/ `area_m2` / `n_points`；
一致性检查（数量、id 唯一、行序、有限值、维度、轮廓可回推、经纬度合法、重建字节一致）
由 `earthglyph/data/index.py` 与 31 个单测强制；
float32 舍入实测最大绝对误差 features 6.7e-7 / shapes 6.0e-8（对检索无影响，但已记录）。

**D32 pending 类别不并入正式索引；失败类型 A/B 只准备字段不下结论** — 已定
依据（`experiments/p0_feature_probe/pending_summary.json`，只读分析，`pending_analysis.parquet` 未删改）：
1,034 个 feature / 1,035 个 part，其中 310 个低于 0.1 ha、725 个可过面积下限；
`water`（836）与已发布候选高度冗余（到最近候选的描述子 L2 中位 0.01629，

## 查询抽象与两级检索（P0-4，2026-11-05 新增）

**D33 镜像策略只在几何精排里实现（`align(query, candidate, allow_mirror=False)`）** — 已定
依据：D26 修订证明 Fourier 幅值在走向规范化后对镜像**精确不变**，因此"默认禁止镜像"若写在
特征层，就只是依赖未规范化输入的一个偶然数值差异，不可靠也不可解释。
影响：`earthglyph/retrieval/alignment.py` 把候选的规范镜像谱取 `conj(B̂)`（免第二次 FFT），
默认只算 direct 分支；`allow_mirror=True` 时同时算两条，按更小的 D 决定 `mirrored` 字段，
并把 `direct_distance` / `mirror_distance` 一起返回，使"镜像是否被采纳"可审计。
实测：镜像查询对同一候选 direct D=0.0749、mirror D=0.0010（`tests/test_alignment.py`）。
镜像与"点序反转"在实现上分开：反转经 `ensure_ccw` 还原为同一条走向（D=A），
反射则始终产生新的几何（D>0），二者不得混称。

**D34 闭式循环移位 + 旋转对齐：θ 由复数相关求，s 由一次逆 FFT 全量求** — 已定
依据：任务明确禁止遍历 360 个角度；且 `D²(s)=E_a+E_b−2|C_s|`、`C_s=IFFT(Â·conj(B̂))_s/N²`
使全部 N 个起点的**最优** θ 同时得到，无需近似网格。
影响：`align` / `align_library` 返回 `(D, s, θ, mirrored)`；单测与"逐移位暴力扫描"在
1e-9 内一致，旋转 / 循环起点不改变最优 D（只改变 achieved transform）；
对称形状报告等价最优个数 `alternatives`（圆 = 128、正方形 = 4），确定性取最小索引。
闭式做两次 O(1) 量级相减，**数值地板 ≈ √eps ≈ 2.1e-8**：低于该值不可区分于完全重合，
所有"零距离"断言按 1e-6 阈值写，不宣称 8 位小数精度。

**D35 手绘查询的完整性 / 自交 / 平滑判据一律以轮廓自身 RMS 尺度为基准** — 已定
依据：任务要求阈值"相对于图形尺度定义"，像素或绝对坐标阈值会让同一图形在不同画布上
得到不同判定；且抽象的目的不是把草图美化成标准图形。
影响：`earthglyph/geometry/sketch.py` 以 `trace_scale`（质心 RMS 半径）为尺子——
重复点容差 `1e-3`、自动闭合端距 `≤0.03`、开放拒绝 `≥0.15`、退化下限（等周比）`1e-3`、
自交是否"结构性"以凸包面积占比 `0.005` 判定；平滑为循环高斯低通（FFT，零相位），
预设 `none / light(σ=0.8) / medium(σ=2.0)`，可显式选且面积保持 ≤2e-3，
`light` 保留凹口（偏差 0.0141）而 `medium` 抹平（0.0547），代价是 16 次谐波能量
分别衰减 17.8% / 70.7% —— 平滑档位因此必须进实验记录，不得凭"更好看"选用。
PNG 输入只取笔画中线（外环 + 最近孔洞环配对），线宽 3/6/12 px 的偏差 < 0.05 尺度，
y 轴向下在几何坐标处翻转；歧义图像（多个分量 / 文字 /  fills 占比越界）**报错而非猜测**。

**D36 `closed=true` 的轨迹末点是"闭合弦"而非几何顶点** — 已定
依据：闭合声明意味着"回到起点"由声明隐含、不是画出来的，故 `close_trace` 取
`outline = points[:-1]`。P0-4 早期据此发现一个真实方法学缺陷：只位移末点的"端点闭合误差"
探针在**接受**分支上完全测不出东西 —— `gap-r294-0.06` 与 `gap-r294-0.35` 提取出的 128 点轮廓
逐点完全相同（最大差 0.0）。
影响：闭合误差探针必须位移**一段尾部**（`open_end(..., ramp=…)`）。尾长按周长定义
（`ramp × 周长`，下限 `TAIL_MIN_STEPS = 6` 个采样步）而非按尺度：枝状轮廓一步即可超过尺度的 15%，
按尺度定义的旧 ramp 退化成了单顶点位移。修尾长后实测尾部跨 11–17 个采样点，
合法缺口（0.06 尺度）内对真值距离从 0.0163 → 0.0228、0.35 尺度从 0.1063 → 0.1643，**排名不变**。
单测 `test_the_closing_vertex_is_a_chord_not_geometry` 钉住该语义。

**D37 图像输入用"笔画带 vs 封闭区域"合取判据拒绝未闭合笔画** — 已定
依据：任务要求线宽 / 抗锯齿 / 背景不得成为几何，且开放曲线不得被猜成形状。
影响：`contour_from_image` 在 `width_rel < OPEN_STROKE_WIDTH_REL(0.05)` **且**
`solidity < OPEN_STROKE_SOLIDITY(0.10)` 时报错（合取，单一条件会误杀真实细长期候选）。
库内校准：最细真实候选为 row 419（width_rel 0.0651 / solidity 0.1598）、536（0.0919 / 0.1699）、
420（0.0975 / 0.1600+）；3–4 px 的 270° 弧为 (0.034, 0.057) → 落在判据内被拒。
多分量 / 文字同样报错，不挑选"最大的那个"。

**D38 对称 Chamfer 只能作复核，不能裁决镜像或旋转** — 已定
依据：实测不变性边界（`tests/test_retrieval.py`）。Chamfer 对两条曲线的刚性运动、循环起点、
走向反转**不变**；对单向旋转或单向镜像**会变**。
影响：镜像裁决只由 `align(..., allow_mirror=)` 承担（D33）；Chamfer 以 `chamfer_top` 窗口复核，
`sort_by="chamfer"` 仅用于测量"两条几何度量是否给出不同顺序"，P0-4 实测 9 个类手绘查询中
3 个 Top-1 改变（心形 PNG / 十角星 JSON / 十角星 PNG），**无人工标注时不宣称哪个更符合肉眼**。

**D39 平滑档位的取舍用可测代价，不用观感** — 已定
依据：任务明确"不要因为平滑后的图形更好看，就认为其更适合搜索"；且档位必须可切换、可复现、可参数化。
影响：默认 `light`。全库 839 条实测（`experiments/p0_retrieval_baseline/notes.md` §4）：
`light` 保留 k=9..16 谱能量占比 0.831（最差 0.760）、\|Δcompactness\| 均值 0.0148 / 最大 0.0940、
\|Δperimeter\| 均值 0.0206 / 最大 0.2761；`medium` 仅保留 0.337（最差 0.197）、最大改动 51% 周长。
**G2 全部扰动族在 none / light / medium 下 Top-1、Top-10 与失败归类完全相同**
（每档 45 个 ok 行中 44 行为第 1），差别只在对真值距离（`none` 最小）。
因此"平滑提升检索命中率"在本轮**不成立**，`light` 只是抖动与细节保留的折中，
且任何结论都必须带档位列。

**D40 三种 baseline 的距离不可跨方法比较；可视化对齐只用于展示** — 已定
依据：`cv2.matchShapes` 的 I23 值域与栅格化尺度相关（同一形状对，实测 0–1.1e-4），
Fourier 粗筛欧氏距离 0.003–0.023，对齐精排 RMS 边界偏移 0.052–0.213，三者量纲无关。
影响：① Hu 基线在**统一像素栅格尺度**上计算（否则连 Hu 之间都不可比）；
② 不做任何未校准的混合特征 L2，不把内部距离换算成"相似度百分比"；
③ `topk_*.png` / `baselines_*.png` 用 `apply_alignment` 把候选摆到查询上**只为肉眼可比**，
排序与数值不受绘图影响；④ 方法优劣的判断依据只能是结果叠加图 + 人工标注（P0-6），
"某方法距离更低"不构成证据。

**D41 失败归因只用实测排名；P0-4 粗筛窗口不是瓶颈** — 已定
依据：任务要求区分 A 提取 / B 粗筛 / C 精排 / D 覆盖四类，且"全库精排排序本身不是人类视觉真值"。
影响：`scripts/evaluate_retrieval.py::attribute` 只用四个排名（返回内 / 去重前 / 粗筛全库 /
精排全库）判定：`rank_coarse > 窗口 且 rank_full ≤ top_k` → B；`rank_full ≤ top_k` 但未返回 → C；
**全库 839 条精排后真值仍在 Top-10 外 → D（覆盖或形变）**，放大窗口不可能解决。
实测 241 行：B = 0、C = 0，A = 22 行（10 个输入），D = 30 行（22 行来自 row 294 枝状水库）；
`--sweep 100,200,300` 逐族逐位相同 → 不调整 `shortlist_size`，扩容决策留给 P0-6/P0-7（D32）。
全库精排（`method="align"`）只作诊断路径，不作产品路径。

**D42 结果契约：确定性排序 + 弱命中措辞 + 去重不隐藏审计顺序** — 已定
依据：任务要求"同一输入必须给同一顺序""不得把内部距离包装成未校准的相似度百分比"，
且 Top-10 不能被同一 `source_id` 的近重复刷屏。
影响：① 排序主键是距离，**并列由稳定 argsort 按索引行序打破**（`kind="stable"`，行序即
`77b083c9` 索引的 `feature_row`），因此除 `timings` 外两次运行逐字节一致（P0-4 实测三次相同）；② `align_distance > WEAK_ALIGN_DISTANCE = 0.12`
时结果带"只是当前库中最接近的候选"的显式告警，不换算成百分比、不声称视觉相似
（本轮星形 `f…` D≈0.21、forked 0.162、crescent 0.157 属此类，D≈0.12 只是本项目内部经验阈值，
**不是**肉眼相似判据，人工标注留 P0-6）；③ `max_per_source=1` 只作用于返回列表，
`SearchResult.pre_dedup` 保留去重前完整顺序供归因（D41 的 C 类判定依赖它）。

## 端口忠实度的归因边界与栅格化契约（P0-4.6 Checkpoint 7 · CP7-A，2026-11-09 新增）

- **D57 端口在"输入可对齐"处达到机器精度，故 H2 头部残差属输入溯源；但未对齐的 7 例记为"未归因"** —
  实测：对 15 个 H2 形状搜索"循环起点 × 遍历方向 × 存档两文件"后，**8/15 的 KerNet2 输出与作者发布 22 维坐标
  差 < 1e-6（对齐后中位 1.5e-07）**，而原生相位中位为 1.5e-02。机器精度同时钉死权重读取、层序、
  conv/pool/ReLU 序、C-order flatten、`inpolygon`、`flipud` 与两级重采样。
  剩余 7 例（索引 3,4,5,7,8,9,10）在完整搜索后仍处 **4.8e-3–1.8e-2**，对齐后全 15 例的 RMSE 下界 1.5e-03
  亦小于头部 6.5e-03 但不等零 ⇒ **禁止**把全部残差说成预处理造成；这 7 例的差值属"存档轮廓 ≠
  产生发布坐标的那份轮廓"，**归因尚未完全证实**。
  KerNet1 独立处理：768 维输入**次序**经消融确认（列主序 x-then-y 中位 0.184 对行主序 1.922 对 y-then-x 2.622），
  但 Figure 8 存档 `c` 是显示轮廓、`Figure8.m` 不再生成网络输入 ⇒ **KerNet1 的网络级忠实度未钉到机器精度**，
  其 0.0597 RMSE 只**部分**归因。H1 与原始 MDS 的差异始终属**近似能力**（D54 的 (a) 侧），不是移植错误。
- **D58 非法输入显式拒绝 + 栅格化改为 MATLAB 原语直译** — 两项**有意**偏离/收敛：
  ① MATLAB 无输入守卫（`adjustContourPos` 除以 `max-min` 会产 NaN），端口改为抛
  `ShapeCompInputError(ValueError)`（全协点 / <3 顶点 / 非有限顶点 / 无 extent），因为 NaN 或零向量下游会
  看起来像合法 ShapeComp 坐标；自交环**继续接受**（`GANinput2shape.m` 明示 GAN 形状可自交，属官方输入类）。
  ② 填充规则从 GEOS `covers` 换成 `inpolygon` 的直译（偶奇交叉数、边界算内部、半开区间去重顶点），
  理由同上：GEOS 对无效多边形无保证的填充语义。**一致性降级为回归测试**：在 15 条 H2 + 60 条 Figure 8
  轮廓（含自交）上逐像素 0 差异，故替换未改变任何栅格化结果。
- **D59 KerNet2 的栅格化敏感性是旋转包装的硬上界（数值已测，推论 CP7-C 已复核：一半成立、一半被证伪）** —
  40×40 图**单像素翻转**即令 22 维输出移动中位 **0.2887 = 18.5% 的坐标范数**（p90 0.3474、max 0.4066）。
  因此"旋转轮廓后再栅格化"是**近不连续**操作，1–4% 量级的残差远小于一个像素，不能按像素误差解释。
  **CP7-C 复核（`results/d6_rotation_metrics.json → image_axis_convention_check`）**：
  ① "R1 细网格对图像路收益有限"**成立** — S0K2 从 24 步到 72 步 agreement 只 +0.0097
  [0.0047, 0.0153]、同族 Top-1 0.514→0.542，代价 3× 查询耗时（0.209→0.626 s）。

  Top-1 稳定性 0.9722 为全场最高。正确解读是：偏差是**给定轮廓的确定性函数**，故同一形状在任何姿态下
  落到同一个（可能歪的）掩膜朝向 ⇒ **不连续性来自"每次重画掩膜"，不来自"朝向没摆正"**。

## D5 旋转压力研究的统计单位与角度因子（P0-4.6 Checkpoint 7 · CP7-B，2026-11-09 新增）

- **D61 D5(a) 的推断单位是"被评分的形状对"（250），不是 1750 行；旧 CI 全部作废，点估计不动** —
  `bootstrap_two_level` 对 `np.tile(ratings, (7,1))` 得到的 1750 行独立重抽样，等于把同一形状的 7 次
  重复观测当作 7 个独立受试材料，并把同一评分面板当作独立重复 ⇒ 区间系统性偏窄。新方法
  `bootstrap_grouped_two_level` 以整簇（一对的全部 7 行同进同出）+ 观察者面板两级重抽样，且**所有臂共用
  同一次 replicate**，因此臂间差是配对比较。实测区间变宽 **×1.49–2.13**（E0 最甚）。
  **重分析不得重跑打分**：`--stage d5b` 只读 `d5_rotation_results.csv`，并用"旧 bootstrap 必须复现
  `d5_rotation_metrics.json` 全部数值"作为准入闸门（实测最大偏差 **0.000e+00**）；**既有 D5 结果文件一字未改**
  （SHA256 + 字节数写入新产物并有测试复核），新结论只写入 `d5_grouped_*` 与 `metrics.json` 的**新增**块。
  后果（21 个臂对的配对比较）：19 个次序成立；**E1 vs S0K2+rot**（+0.0085 [−0.0287,+0.0467]）与
  **S0K1 naive vs S0K2 naive**（−0.0239 [−0.0496,+0.0015]）**不可区分**，此前只给点估计容易被读成排序；
  被朴素边际区间掩盖的 5 个差由配对检验补上。**没有任何旧排序被推翻**，被推翻的只是精度。
  **独立复核（不依赖本轮改动）**：D1 未旋转、其 bootstrap 本来就以 250 对为单位 ⇒ 对"旋转不改变距离"的臂，
  修正后的 D5 区间必须与 D1 重合。实测宽度 E0 **0.1468 = D1 0.1468**、E1 **0.1159 = 0.1159**（逐位相同）、
  E3 0.1054 vs D1 0.1066（差 0.0012，因 E3 的旋转搜索确实随角度改变距离）；两个 naive 臂相反地**宽于** D1
  （0.146 vs 0.065）——其一致性真的随所抽角度而变。故"CP6 的 D5 区间约为应有宽度的一半"由第三方数字证实。
- **D62 头部口径 = 角度为固定设计因子；"随机角度"只作敏感性，不得混用** — 七个压力角度是预先声明的设计集，
  故头部区间回答"这套协议、换一批形状与观察者"。若把角度本身也按有放回抽样（三级重抽样），
  旋转鲁棒臂几乎不动（E3 [+0.7533,+0.8640]），而 naive 臂剧烈变宽（S0K1 宽度 0.113 → 0.453），
  并有两个次序失效（E1>S0K1+rot、S0K2+rot>S0K1+rot）⇒ **凡引用这两条须限定"在本轮声明的角度集上"**。
- **D63 旋转后沿用原有人类评分只是假设，不是新人类数据** — 250 对 × 7 角度共用同一份已发布评分，
  前提是"旋转其中一个成员不改变被试感知到的相似度"。本轮**未**复测任何旋转对，也不存在新的评分。
  因而 (a) 的 agreement 度量的是"对图像变换的不变性"，**不是**"人类对旋转形状的判断一致性"；
  主判据仍是 D54 的 (b) 检索，本条不得被升格为人类感知证据。

  实测其 7 个角度 agreement 曲线**完全同一**（差 0.000e+00），并用真实轮廓验证过这不是"旋转被丢弃"：
  `scripts/verify_r2_pose_invariance.py` → `results/r2_pose_invariance_check.json`，同一 contour 在
  37/191/270° 下 **naive 坐标移动 0.61–2.04**（坐标范数约 1.22，即超过自身长度），
  而 R2 在**有主轴的 11 条**上仅移动 **≤5.1e-14（KerNet1）/ 恰好 0.0（KerNet2）**；
  第 12 条 `device2-1` 是冻结集中唯一的 `isotropic-fallback`，其 R2 移动与 naive **逐位相同**
  （0.1523/0.4336）⇒ 无轴形状上 R2 **等价于不做任何事**，此结论按形状报告而非取平均。
- **D68 R3 的 24×24 图库预缓存必须计入成本，且不得当作 24 个独立对象** — 预计算
  `gallery_pose_embeddings`：S0K1 **22.4 s**、S0K2 **78.4 s**（一次性，按 network×strategy 缓存），
  查询侧 0.086/0.231 s。多姿态是同一形状的姿态行，检索仍每形状一个条目；
  `pose_embeddings()` 对 naive/R0/R1 直接复用 `kernet_coords()[:, None, :]`，并有确定性测试钉住，
  保证包装器不能对"候选是什么"给出与朴素臂不同的答案。
- **D69 错误吸引在 naive 臂上为负、在包装器上为正，故包装器不只是把自匹配拉近** —
  `attraction_gap_mean`（目标距离减最近异类距离，正=更安全）：S0K1/naive **−0.273**、S0K2/naive
  **−0.263**，而 R0/R1/R2/R3 全部为正（0.248–0.593）。同时 naive 的 Top-10 与未旋转重合仅 0.28–0.29、
  平均绝对排名位移 **46** 位；R2 位移 0.27/0.68 位。⇒ 旋转不变性问题真实存在，且 R2/R3 改善的是排序结构本身。
- **D70 R2 朝向规范化用了第三矩符号，与 E1 的容差不互通** — 180° 歧义由环坐标第三矩符号决定，
  `ISOTROPY_MAX=0.98`、`SIGN_TIE_TOLERANCE=1e-3`；E1 的 `principal_frame` 用面积矩与 `1e-9`。
  **两套口径不能互相冒充"the canonicalisation"**：CP7-D F1 实测 E1 侧残差 |η30| 常在 1e-17 量级
  （即由浮点噪声定符号），而该情形下描述子漂移只是丢轴情形的 ~1/80。
  近似圆/正多边形/五角星触发 isotropic fallback（无轴可对），R2 在**这些形状上并不等价于**朴素不变。
- **D71 目标 A 与目标 B 必须分表报告，本轮不得合并成"综合更好"** — 同一臂在两个目标上排序不同：
  agreement（人类一致性）最高 **E3/sample 0.839**、R3 0.830/0.829；T2 检索 Top-1 最高 **E1 0.833**。
  禁止用 A 的高 ρ 掩盖 B 的失败（naive：ρ 0.434/0.458 且 T2 Top-1 0.264/0.250 同时崩塌），
  也禁止用 B 的自匹配精确宣布感知已完善（R2：稳定性 0.972 而 ρ 仅 0.677）。

## 接口真实性、术语与工具箱来源（P0-4.6 Checkpoint 7 · CP7-D，2026-11-09 新增）

- **D72 F2：`allow_mirror` 在无镜像分支的臂上改为显式拒绝，而非静默无效** —
  `MIRROR_AWARE_METHODS = ("E0","E1","E3")`；`search_shape`/`pair_distance` 对 S0/S0K1/S0K2 传
  `allow_mirror=True` 直接 `ValueError`（`_require_mirror_support` 在载入权重之前触发，故无工具箱也能测试）。
  **理由**：给官方臂加一次镜像前向是新能力，须作为独立臂评价（同 CP7-C 的旋转包装器），
  不能藏在一个布尔后面；"参数看似有效、实际无效果"正是本轮要点名的失效模式。
- **D73 F2 连带发现并修掉两处更隐蔽的"静默无效"**（均为真实缺陷，非测试便利）：
  ① `score_library_from_descriptors` 只在**报错**时看 `allow_mirror`，打分循环却无条件读取
  `cached.mirror_contexts`——因此**含镜像的缓存会让每个查询悄悄用上镜像**，与自身 POLICY
  ("only when allow_mirror=True") 相反；现改为 `mirror = cached.mirror_contexts[row] if allow_mirror else None`。
  ② E1 的 `fit_normalizer` 对"仅由浮点残差变化"的列仍做 minmax 除法：实测 H1 语料有 **6 列**
  全库极差 5e-17–4e-16（数学上恒定量），除以自己的残差后把它们放大成 2.4–8.6 的距离，
  使"查询自身镜像"的描述子离查询 11.7 而直接匹配 7.0 ⇒ **镜像分支永远不可能胜出**。

  **基线未动证明**：两套真实语料被标记的列数 6→6、5→5，**改变 0 列**，最小真实极差 2.46e-4/2.09e-3
  比地板高 5–8 个数量级；`shapecomp_port_validation.json` 重跑后 diff **仅 1 行文字、0 个数值**。
  ③ 顺带修 `Gallery(..., e3_params={"allow_mirror": True})` + `search_shape(method="E3")` 的

## 符号约定、臂集合守卫与过期汇总（P0-4.6 CP7 收官后的修复轮，2026-11-09 新增）

  机制：`bootstrap_grouped_two_level` 的每个 replicate 是 `spearmanr(距离, 人类**相似**)`（越负越好），
  配对差取 `values[first] − values[second]`，而发布的 agreement 又把该相关取负 ⇒ **两次取负相消**，
