手绘查询板 — 把真实的一笔一画交给检索

这是 P0-4 的算法调试工具，不是产品界面：它只负责采集指针轨迹并导出 JSON， 轮廓抽取、标准化、检索都在 Python 端。导出的点是画板坐标，但已在导出时把画板向下的 y 轴翻成数学坐标系（y 向上）——否则交出去的就是一个垂直镜像的形状，而镜像默认不参与匹配。 轨迹不做任何平滑、补点或模板化：工具的职责是保留你真正画出的形状。 画完点“直接检索”可经本地小服务（scripts/serve_sketch_search.py） 立即看到真实索引的 Top-10；导出 JSON 交采集脚本的路径不变。 M1 多笔画：1 笔仍导出旧格式；2–8 笔导出 schema v2（strokes）， 由 Python 端拼接成一条闭合轮廓——开口过大、自交或存在多种同样合理的拼法时会拒绝并要求重画， 程序不替你封口，也不在歧义时替你挑选。多笔输入不进入 P0-6 真人数据采集。

单笔：“首尾间距”按形状的均方根半径归一；间距超过 0.15 且不是采样接缝时报 open stroke，要求重画——这里提前显示，是为了让你当场重画，而不是让程序替你封口。 多笔（2–8）：Python 端按端点距离（≤0.03×形状尺度）与转角（≤150°）找接头， 全局搜索把所有笔画恰好用一次拼成一条简单闭合环；明显缺口不桥接， 多种同样合理的拼法报 ambiguous，同样要求重画。

点击行切换叠加图：红虚线 = 你画出的原始笔迹（仅平移 + 统一缩放，质心/RMS 按弧长均匀统计，与检索同帧；不重采样、不平滑；多笔模式逐笔开放绘制，不自动闭合）， 琥珀点/短线 = 系统生成的接头（仅多笔：吸附点与两端点间的短连接段，是假设不是笔迹）， 灰细线 = 检索实际使用的标准化轮廓（128 点弧长重采样 + 轻度平滑）， 绿实线 = 候选在匹配器实际拟合姿态下的轮廓。 红灰两线的差异就是标准化（多笔时还含拼接吸附）引入的全部改动；闭弦/平滑/吸附等假设会列在上方告警里。 D 是归一化边界偏移（形状半径的比例），不是相似度百分比； 弱命中告警原样显示。此面板是调试视图，不构成 P0-6 真人数据。
