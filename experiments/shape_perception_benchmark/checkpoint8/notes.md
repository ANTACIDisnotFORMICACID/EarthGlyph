# P0-4.6 Checkpoint 8 笔记 — 先把指标读对，再在新的形状查询上重测旋转包装

> **性质：统计修正（CP8-A）+ 独立验证的实跑记录（CP8-B/C）。**
> 本目录不训练模型、不改算法数学定义、不动官方 ShapeComp 权重、不引入真实水体数据库、不进 P1 Web 开发。
> 一句话结论的读法：**类别检索正确 ≠ 人眼相似 ≠ 旋转后结果稳定 ≠ 计算成本合理**，四件事分别看，
> 任何单一指标都不构成"最终赢家"。

## 2. 两套分母（CP8-A 的规矩，CP8-C 一开始就按它写）

- 每（臂 × 条件）：**120 个旋转格**（24 查询 × 5 个非零角度）+ **24 个 control 格**（精确 0°）= 144 格。
- headline 只从 `rotation_only` 取；`unrotated_control` 是接线诊断，它的 `top1_stability_vs_unrotated`
  **按构造恒为 1.0**，因此永远不能当作"扛住了旋转"的证据。
- 两堆格子由 `slot` 区分，`slot` 与 `angle_deg` 一旦矛盾就 `raise`；0° 原始行一行未删。
- bootstrap 以**原查询**为聚类单位（24 簇，每簇带着它的 5 个格子一起被抽），
  所以 120 行 ≠ 120 个独立观测；区间宽是样本量的真实反映。

### 2.1 一个必须如实记录的抽样事实：同一查询可能抽到重复角度

冻结的槽位采样器对每个查询**独立地**抽 5 个非零角度（1 个 `on_grid` + 2 个 `mid_grid` + 2 个 `random`），
`mid_grid` / `random` 各自带随机抖动，且**没有"不许重复"的约束**——所以两次抽到同一个角度是设计的允许结果，
不是采样 bug。实测在这 24 个查询里恰好发生一次：`lizzard-3`（设计第 22 条）的两个 `mid_grid` 槽都是 **127.5°**。

后果全部核实过，并按 brief"不允许观察结果后更换失败查询或重新抽角度"的要求**只记录、不修复**：

| 量 | 值 | 说明 |
|----|----|------|
| 每（臂 × 条件）的格子数 | 120 旋转 + 24 control = **144**（不变） | 统计单位是"格子"，不是"不同的姿态" |
| 其中不同的 (查询, 角度) 组合 | **143**（旋转侧 119 而非 120） | 127.5° 在 `lizzard-3` 上被抽了两次 |
| 重复的 T2 格 | **6**（6 臂各 1 个） | 全部是 `lizzard-3` / `mid_grid` / `127.5°` |
| 重复的命中行键 | **120**（12 组 × 10 名次；T2 侧 60） | 逐字核对：候选 ID、类别、距离、同类标记**全部一致**，0 组不一致 |
| 表内重复行除 `elapsed_seconds` 外的列 | 完全相同 | 两次是**同一输入上的两次搜索**，结果可复现 |
| `cp8_full_rankings_T2.npz` 的条目数 | **858** = 6 × 143 | 不是漏写；键去重后本就只有 858 个 |

读法上的两条硬规矩（都已写进代码，不是提示）：

1. **任何按 (臂, 查询, 姿态) 键回查存储结果的代码必须是"分组 + 一致性检查"，不能是一对一查找。**
   `scripts/plot_checkpoint8.py` 的 `pose_hits()` 就是这么实现的：同一键的多行若候选或距离不一致，
   它直接 `SystemExit` 说明"这一姿态被存成两次不同的搜索"，而不是静默取第一行。
2. **重复角度影响的是有效样本量，不是口径。** 该查询的 127.5° 被计了两次，
   所以 120 格背后的独立姿态只有 119 个；聚类 bootstrap 把整簇一起抽，这一点没有被掩盖，
   但报告"120 个旋转姿态"时必须能说清"120 格 / 119 个不同姿态"。

## 3. 逐格表列的读法（31 列）

| 列 | 含义 | 容易读错的地方 |
|----|------|----------------|
| `arm` / `method` / `rotation_strategy` / `orientation` | 臂标签与它的两个自由度（网络 × 包装） | `S0K2/R2` 与 `S0K2/R3` 只差包装，不比网络 |
| `condition` | `T2` 主条件（删自身+近重复）/ `T0` 接线校验（全库、目标在场） | T0 的绝对值不能和 T2 并列比较，更不能和 D6 的 5-per-class 子库并列 |
| `query_id` / `family` / `query_class` | 查询、家族标签、MPEG-7 类别 | `family` 是设计侧的形状描述，不是数据集真值；`query_class` 才是可核对的标签 |
| `slot` / `angle_deg` | 角度槽（`on_grid` / `mid_grid` / `random` / `control`）与实际角度 | control 的 `angle_deg` 必须是 `0.0`；`random` 是全精度浮点，不是整数 |
| `n_kept` / `n_same_class_kept` | 该条件下图库剩余数 / **剩余同类候选数** | 后者就是 Recall@10 的分母，逐查询为 2/3/4 量级，**不是固定 10** |
| `same_class_hits_at_10` | 前 10 名里同类的个数（分子） | 与 `cp8_top10_hits.csv` 逐行数应当完全一致（测试钉住） |
| `top1` / `top1_is_target` / `top1_is_same_class` / `top1_matches_unrotated` | Top-1 是谁、是否精确目标、是否同类、是否与未旋转那次相同 | T2 下 `top1_is_target` 恒为 0（目标被删），这不是失败 |
| `target_rank` / `self_distance` / `best_wrong_class_distance` | 精确目标的名次与距离、最近的**异类**距离 | `target_rank` 在 T2 为空——空值不是 0，也不是缺失错误 |
| `precision_at_10` | 返回清单里同类占比（分母 = `min(10, 返回数)`） | 这就是历史上被叫作 `class_recall_at_k` 的量 |
| `recall_at_10` | 找回了多少**还留在库里**的同类；一个同类都没留时为空 | 空值计入 `recall_at_10_undefined_cells`，不当 0 分混进均值 |
| `first_relevant_rank` / `ndcg_at_10` | 第一个同类出现的名次 / 增益折损 | NDCG 只在有相关项时定义，汇总里带 `ndcg_at_10_n_scored` |
| `top_10_overlap_vs_unrotated` / `mean_abs_rank_shift` / `max_abs_rank_shift` / `spearman_between_rankings` | 与该臂**自己**未旋转那次的全清单重合 / 位移 | 参照物是同一臂的 control 格，不是别的臂，也不是别的条件 |
| `forward_passes` / `query_poses` | 该次搜索的推理次数与姿态数（仅 ShapeComp 臂有值） | 这是成本证据，不是质量证据 |
| `elapsed_seconds` | 该次**搜索**的墙钟 | 一次搜索同时喂给 T0 与 T2 两行，两行的值**完全相同**（858 组全部核实），所以按列求和会把每次搜索数两遍（见 §6）；与 `forward_passes` 一起看才说明"贵在哪" |

## 5. 本轮实测 headline（四轴分开，T2 主条件 · `rotation_only` 视图 · 120 格）

| 臂 | ① 类别检索正确 | ② 旋转后结果稳定 | ③ 全清单重合 | ④ 计算成本 |
|----|----------------|------------------|--------------|------------|
| | Top-1 同类 [95% CI] | Top-1 与未旋转一致 [95% CI] | Top-10 overlap | 秒/次搜索 |
| `E0` | 0.833 [0.667, 0.958] | **1.000** [1.000, 1.000] | 1.000 | 0.123 |
| `E1` | 0.792 [0.625, 0.958] | **1.000** [1.000, 1.000] | 1.000 | 0.031 |
| `E3/sample` | **0.858** [0.725, 0.967] | 0.550 [0.417, 0.683] | 0.707 | **56.10** |
| `S0K1/R3` | **0.858** [0.717, 0.967] | 0.542 [0.417, 0.675] | 0.720 | 0.163 |
| `S0K2/R3` | 0.825 [0.683, 0.942] | 0.483 [0.358, 0.617] | 0.670 | 0.301 |
| `S0K2/R2` | 0.833 [0.708, 0.958] | **1.000** [1.000, 1.000] | 1.000 | **0.008** |

另两条轴（同一批格子，不改变上面的读法）：Precision@10 = 0.675 / 0.725 / **0.745** / 0.678 / 0.630 / 0.538；
Recall@10（分母 = 该查询自己留在库里的同类数，逐查询不同）= 0.365 / 0.397 / **0.404** / 0.366 / 0.338 / 0.294；
NDCG@10 = 0.713 / 0.747 / **0.778** / 0.715 / 0.668 / 0.596；class MRR = 0.871 / 0.861 / **0.899** / 0.884 / 0.863 / 0.866。

四点必须一起说：

- **①与②不重叠**：三个姿态盲的臂（E0/E1/S0K2/R2）稳定性按构造是 1.000，因为它们的输出根本不随姿态变；
  三个 R3/采样臂在 0.48–0.55 之间。而 Top-1 同类准确率六臂全在 0.825–0.858 的窄带里，
  区间大面积重叠——**这批数据不支持"旋转包装在新的查询上提高了类别检索正确率"**。
- **④与①的取舍方向相反**：最便宜的 S0K2/R2（0.008 s）与最贵的 E3/sample（56.1 s）在①上差 0.025，
  在②上差 0.45。用②去换④，或反过来，都是同一笔交易的两面。
- **T0 接线校验**（目标在场、全库）：E0/E1 的 Top-1 精确命中率 1.000，S0K2/R2 0.958，
  R3 与采样臂 0.75–0.82。这一列只证明"管线接对了"，不与 T2 并列比较。
- **④ 是本轮的边际搜索成本，不是该臂的重构成本**：六臂的图库侧一次性开销都在
  `provenance.precompute_seconds`（图库 11.489 s + 姿态嵌入 382.9 s）里单列，
  其中 E1 那 11.489 s 是 91 维描述子的整库抽取——它在本轮只付一次，之后每次搜索命中缓存。
  详见 §6"④ 是命中缓存的边际成本"。

## 6. 边界与已知缺口（不得讲成已完成）

- **人类感知：本轮 0 份新评分。** 独立验证只覆盖"类别检索 + 旋转稳定性 + 成本"，
  人类感知一侧仍然只有 H1 的 250 对评分表，且那是**另一批材料**，不与这 24 个 MPEG-7 查询混算。
- **近圆（各向同性）家族未被覆盖**：设计的自审判据 `coverage_audit` 里 `near_circle` 达标 **0/4**
  （17/24 总体达标）。按 brief 要求只记录不修复——不换查询、不重抽角度、不放宽阈值。
  因此本轮**不能**说"旋转包装在圆形上被证明无用"，只能说这一格没测。
- **图库与 D6 不同**：CP8 用整个 MPEG-7 档案（1 398 个可用轮廓），D6 用每类 5 个的子库；
  跨表只引用**方向与排序**，不逐位比大小。
- **24 查询是承诺的样本量，不是大样本**：区间宽、重叠是正常的；臂是 16 臂里选出的 6 个，
  结论不外推到未跑的 10 臂。
- **E3/sample 昂贵**：全库单次搜索实测 ~55.7 s，是整轮墙钟的主导项；成本结论按 `elapsed_seconds`
  与 `forward_passes` 报，不为"看起来快"而少跑难例。
- **成本列不能按行求和**：一次搜索的墙钟同时写进 T0 与 T2 两行（858 组逐组核实数值相同），
  所以对 1 728 行直接求和得到 16 369.6 s，是真实搜索时间 8 184.8 s 的两倍。
  要总量就按 (臂, 查询, 姿态) 去重后求和，或只看 `seconds_per_query_mean`（视图内的均值，不受影响）。
- **④ 是"命中缓存的边际成本"，不能与 D2 的 12 s 并列**：E1 的 91 维描述子由
  `features_for_library()` 按**候选集合的内容哈希**缓存（`perceptual_features.py:1133`，
  最多 4 个集合，`:236`）。CP8 只搜索同一个全图库、把删除作用在打分之后，所以图库构造时那一次
  抽取（`provenance.precompute_seconds.gallery` = 11.489 s）之后每次搜索都是命中——
  实测 0.03 s；而 D2 的循环里每个条件都换一个新的候选子集，未命中时要**重新抽取整个子集**，
  实测 10.9–11.0 s/次（`d2_metrics.json` 的 E1 `elapsed_seconds` 因此是双峰的：21 格 11.1–11.3 s、
  3 格 0.031–0.032 s，取决于那一格是否恰好命中缓存）。
  两列都记的是"这一次 `search_shape()` 的墙钟"，但**缓存状态不同**，
  所以"CP8 测得 E1 只要 0.031 s"不能改写成"E1 比 D2 记载的快 380 倍（12 ÷ 0.031）"。
  跨表只比较同一次搜索内部的臂间排序。
- **120 个旋转格 ≠ 120 个不同姿态**：见 §2.1，`lizzard-3` 的 127.5° 被抽到两次，独立姿态只有 119 个。
