# P0-6 — 真人手绘查询采集与盲评协议（冻结于任何采集之前）

> 状态：**协议冻结，尚无任何真人数据**。本目录在采集开始前只包含协议、模板与
> 采集脚本；`sessions/` 为空。**禁止**用算法生成的内容、AI 评分或作者自绘冒充真人数据。

## 0. 目的与边界

P0 门禁的唯一入口（`docs/EXPERIMENTS.md` §6）：在**≥10 个不同真人**手绘轮廓上测试生产检索器，
回答"多数查询能否在 Top-10 找到肉眼明显相似的真实地物"。
本协议只规定**怎么采、怎么评、怎么判成功**；不实现任何 Web 产品界面。

- 合成扰动（P0-5）的检索成功率 ≠ 真人命中率；两者永远分开报告。
- 抽屉自评（"这画的是我"）与独立盲评（第三人判断）是两条独立证据，分开统计。

## 1. 参与者与匿名化

- **≥10 名可区分参与者**，每人分配匿名号 `P01…P99`。
- 参与者可自选代号；`scripts/collect_p06_queries.py` 在本地密钥表
  （`sessions/key_participants.json`，**gitignore，不入库**）里记录 代号→PXX 映射；
  仓库内只出现 PXX。
- 采集时记录且仅记录：设备类型（鼠标/触控板/触摸屏）、是否熟悉所画地物（是/否）、日期。
  不收集姓名、联系方式等任何个人信息。

## 2. 绘制规则（向参与者展示，全文见 templates/participant_instructions.md）

1. 用 `tools/sketch_pad.html` 画，每页一个形状，**一笔闭合**（起终点尽量回到一起）。
2. 凭记忆画指定水体的外轮廓：不许对照地图描、不许看检索结果后再画。
3. 每位参与者 ≥6 幅，覆盖：① 你最熟的一个湖 ② 一个水库 ③ 一个小池塘
   ④ 一条河岸/海湾轮廓 ⑤ 任意你记得形状的水体 ⑥ 自选。
   题目在绘制前固定并记入 session manifest（不得事后替换题目）。
4. 重画允许：所有导出都保留；参与者声明哪一份是最终版（`final: true`），
   评估只用最终版，其余标 `practice`。
5. 导出 JSON（sketch_pad 格式：`points` / `closed` / `unit` / `y_axis` / `canvas`）
   交给采集脚本，**不要**自行改名或编辑内容。

## 3. 采集与登记（scripts/collect_p06_queries.py）

- 输入：导出 JSON 的收件目录。脚本逐文件校验**结构**（points 为 ≥3 个有限坐标的二维数组、
  closed 布尔、单笔画），按内容 sha256 去重，登记到
  `sessions/<PXX>/<query_id>.json`，`query_id = PXX-q<两位序号>`。
- 结构不合法的文件登记为 `invalid` 并保留原文件，**不删除、不修改**。
- **提取拒绝不是采集错误**：自相交、开口过大等由生产提取器在评估阶段如实判定并记录
  （refusal 列），参与者重画按规则 4 处理。
- 脚本只做登记，不做检索、不打分、不生成任何"看似真人"的数据。

## 4. 检索与盲评材料（scripts/make_p06_judgement_sheets.py）

- 对每份**最终版**查询用冻结的生产参数检索一次
  （`search_by_contour`，method=fourier_align，top_k=10，shortlist=200，
  smoothing=light，allow_mirror=False；算法与默认参数在评估日冻结，之后不得更换）。
- 盲评单（每查询一张 PNG + 一行 CSV）：查询轮廓与 Top-10 候选叠加图按
  每查询独立随机顺序排列，标 A–J；**候选身份（row/candidate_id/距离）不出现在图上**，
  对应表写入本地密钥文件 `sessions/key_options.json`（gitignore）。
- 提取被拒绝的查询生成"重画请求"记录，不生成盲评单。

## 5. 盲评规则

- **抽屉自评**：参与者本人对自己每幅的 Top-10 逐一标注
  `similar / weak / not_similar`，并选出"最像的一张"或 `none`。
- **独立盲评**：≥2 名未见过绘制过程的第三方对同一批图重复同一标注
  （评委不得是同查询的抽屉；标注顺序由每评委固定种子打乱）。
- 评分者不知道哪个候选是"算法第一名"——图上没有排名信息。

## 6. 成功判据（采集前冻结）

对**全部有效最终查询**（预计 ≥10 人 × ≥6 幅 = ≥60，实际以登记数为准）：

- **主判据（Go/No-Go）**：抽屉自评 Top-10 中存在 `similar` 的查询占比。
  **Go = 严格多数（> 50%）**；同时报告独立盲评的同一占比与两者一致率。
- **次要判据**：盲评与自评的一致率；归因分布（复用 P0-5 的 A/B/C/D 四类 + 提取拒绝）；
  拒绝率；每查询端到端时延中位数。
- **NO-GO 处置**按 EXPERIMENTS.md §6：改数据/算法 或 调整定位，不在本协议内。

## 7. 采集前预检（scripts/validate_p06_dataset.py）

检索评估运行前必须通过：≥10 个不同 PXX；每人 ≥6 幅最终版；无重复 sha256；
结构校验全部通过或已登记 invalid；密钥文件与本仓库存放目录分离。

## 8. 本轮不能宣称

- 没有真实参与者数据前，不得报告任何"命中率"；
- 不得把 P0-4 的 machine-drawn 指针轨迹（G3）或 P0-5 的合成扰动当作真人手绘；
- 不得在拿到盲评前把任何内部指标称作"人眼匹配准确率"。
