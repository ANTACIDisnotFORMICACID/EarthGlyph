# EarthGlyph Retrieval Skill

本 Skill 规范 EarthGlyph V1（闭合轮廓检索）的算法开发、实验与评价工作流。
它是**工作流程说明**，不代表已安装任何运行时库；实际 Python 依赖见项目 `pyproject.toml`。

## 最高原则（不可被覆盖）

1. **真实数据优先**：禁止伪造真实地理数据、地点或检索结果。禁止用固定地点映射冒充通用检索算法。
2. **可复现**：每个实验必须记录数据来源+版本、随机种子、参数、代码 commit、运行命令，第三方能据此重跑。
3. **区分两类实验**：合成扰动测试（对真实轮廓施加平移/缩放/旋转/噪声）与真实手绘测试必须分开记录，不得混用指标。
4. **诚实评价**：不得只用人工挑选的成功案例评价；必须报告失败案例与整体分布。
5. **未验证不下结论**：没有跑过实验，不得宣称"算法得到提升"。未验证的技术假设写入 `docs/DECISIONS.md` 并标注"假设/待验证"。
6. 本 Skill 服从 `AGENTS.md`；若与项目最高工程规则冲突，以 `AGENTS.md` 为准。

## 前置阅读（每次任务开始）

1. 阅读 `AGENTS.md`。
2. 阅读与本任务相关的设计文档：`docs/RETRIEVAL_DESIGN.md`、`docs/DATA_PIPELINE.md`、`docs/EXPERIMENTS.md`。

不要无差别读取全部文件或加载全部 Skill。仅按当前任务选择必要的 Skill（几何处理→shapely；数据检查/格式转换/CRS→gdal）。

## 标准工作流

1. **明确目标**：一句话说清本次实验要验证什么（例：Fourier Descriptors 在旋转下的 Top-1 命中率是否优于 Hu Moments）。
2. **确认数据**：使用哪个区域、哪个版本、多少有效地物；数据是否已清洗、几何是否有效。
3. **建立/复用 Baseline**：先跑通已有 baseline，记录其指标作为对照。没有 baseline 就先建 baseline。
4. **单一变量**：一次只改一个主要实验因素（特征/距离/归一化/精排方法之一），其余固定。
5. **运行测试与实验**：先跑单元测试（`pytest`）确保几何预处理正确，再跑检索实验脚本。
6. **导出真实 Top-K 结果图**：把查询轮廓与检索到的真实地物轮廓叠加导出为图片，肉眼核验形状是否合理。
7. **对比历史**：与已有实验的指标和结果图对比，判断是提升、持平还是退化。
8. **记录失败案例**：保存明显失败的查询与结果，分析原因（数据问题 / 特征不足 / 归一化缺陷）。
9. **更新记录**：把参数、指标、结论、复现命令写入 `experiments/` 实验日志，并更新 `docs/TASKS.md` 的下一步。

## 检索流水线（V1 约定）

```
轮廓提取 → 几何清洗/有效性修复 → 形状标准化（平移+尺度归一，处理旋转/镜像/起点/方向）
        → 特征计算 → 特征粗筛（近邻检索）→ 几何精排 → 去重 → 地理结果
```

- **标准化**必须处理：平移不变、尺度不变、旋转（对齐或旋转不变特征）、镜像、轮廓点序列起点与方向、采样点数一致。
- **Baseline 特征**：Hu Moments、Fourier Descriptors、Chamfer Distance、轮廓旋转对齐。缺乏 baseline 实验前不引入深度学习模型。
- **粗筛→精排**：粗筛用低维特征做近邻（如 KD-Tree / 向量检索），精排用几何距离（Chamfer / Hausdorff）。

## 评价方法

### A. 算法正确性（合成扰动）
取真实地物轮廓，施加已知平移/缩放/旋转/受控扰动，检查检索能否恢复原始地物。
指标：Top-1 / Top-K 命中率、mAP、rank 分布。必须报告在不同扰动强度下的曲线，而非单点。

### B. 真实手绘检索
用独立绘制的图案检索真实数据库，保存 Top-K 结果图，检查：形状是否合理、匹配是否稳定、结果是否多样、是否有明显失败。
不能只报内部数值指标；必须附真实结果图与人工判断。
